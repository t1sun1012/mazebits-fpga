# User-discovered policy counterexamples

These two mazes were transcribed from monitor photographs supplied after the Step 6 acceptance checks. The exported integer models reproduce the photographed terminal outcomes, attempts, and cycle counters. This is additional Python/physical-board evidence; these cases were not part of the original four-scenario full-system RTL simulation suite. Passing the hardware checklist means the implementation behaves as specified, not that the learned policies solve every editable maze.

The JSON files beside each map record every action, score vector, position, and final result. Coordinates are (x, y), starting at zero in the top-left. Integer score scales differ between precisions; compare scores within one model only.

For IMG_7179, the 8-bit policy goes down four times, then up into a visited cell. The 4-bit policy continues around the wall and reaches the goal. Preserving the floating-point network more closely does not guarantee a better action on every individual maze; quantization can reverse an incorrect action ranking as well as a correct one.

For IMG_7180, the 8-bit policy goes down five times, then up. The 4-bit policy goes down seven times, right, then left. Both revisit a cell, so the controller reports LOOP. The CNN receives the current walls, agent position, and goal, with no recurrent memory or visited-trail input. Repeating a state on this unchanged map would repeat the deterministic decisions. LOOP does not mean the maze is unsolvable.

The [original floating-point replay](long-detour-fp32.json) also goes down five times, then up: it already fails before quantization. At (0, 5), it scores UP above the BFS-optimal DOWN. Thus this case identifies a learned-policy limitation that exists independently of FPGA arithmetic. All 15 integer decisions for this map also agree with the independent scalar integer reference.

Training used 800 layouts generated by independently sampling walls at probabilities 0.1, 0.2, or 0.3. The committed dataset audit reports maximum training BFS distance 24 and maximum validation distance 19; this map needs 26 moves. This supports a generalization gap on long connected barriers and detours. It does not isolate dataset coverage from model capacity or optimization as the sole cause.

A useful next experiment is to generate families of long barriers, corridors, U-shaped obstacles, and goals requiring moves away from their apparent direction; keep unseen layouts and rotations/reflections separate for evaluation. Train against BFS labels, compare complete-route success for FP32/W8A8/W4A4, and retain these known failures as diagnostic cases rather than claiming they remain unseen tests after tuning. First test the existing architecture; consider architecture changes only if broader training still fails. These findings do not require changing the frozen model or current board bitstream.
